# Figure reproduction and archive PR plan

## Objective

Create one cherry-pickable, reviewable figure archive for the paper figures,
user-certified figures, and future Canva exports without silently mixing
unverified candidates, legacy model identities, or diagnostic failures into
publication data.

## What is included now

1. The user-certified Cr three-path Scratch-600K R05 bundle, with PDF/SVG/PNG,
   renderer, the exact plotted-profile summary and coverage audit, materialized
   campaign/model/path manifests, endpoint records, remote pointers, and
   hashes. File Provider-evicted source tables are explicitly pointer-only;
   the original analysis-root R05 commit retains their tracked copies.
2. The materialized 2026-10-28 paper-figure archive, grouped by stable chart
   ID with figures, derived data, manifests, and the reproduction index.
3. A dated SQLite registry snapshot based on that materialized archive, plus
   a byte-identical backup, base snapshot, schema backup, idempotent SQL
   migration, query examples, and an integrity-checking rebuild script.
4. Figure and worktree audit indexes. Historical commits are preserved as
   source references and are not blindly cherry-picked because several are
   whole analysis packages or have explicit scientific caveats.

## Naming and linkage contract

Every migrated chart should have:

- a stable `chart_id` and a date/revision in its directory name;
- `figures/`, `scripts/`, `data/`, `source/`, and `provenance/` subdirectories;
- a chart row plus panel, data-file, link, and provenance rows in SQLite;
- the exact renderer command and output/input hashes;
- an explicit evidence state such as `USER_CERTIFIED_RELEASE`,
  `COMPLETE_WITH_CAVEATS`, `FINITE_DIAGNOSTIC`, `FAILURE_MODE`, or
  `NOT_AUDITED`;
- a source pointer for remote trajectories, external PDFs, or Canva designs;
- no upgrade from scheduler completion or visual approval to scientific
  acceptance without a separate data/provenance gate.

## Cherry-pick order

The current local history already contains the certified analysis-root R05
commit `ea3a30247ed60414f0b5ac056afeeb722cf63925`. The follow-up archive
commit should be cherry-picked after it, or the two commits can be reviewed as
one contiguous release series:

```text
1. Add certified Cr R05 analysis bundle.
2. Add canonical results/plots bundles, figure archive, registry snapshot,
   SQL migration/backups, and audit documentation.
```

The archive commit is prepared on the local branch
`codex/figure-repro-archive-20261101`, parented directly on the certified R05
commit. The exact branch tip is reported with the delivery result so the
cherry-pick target cannot become stale inside this document.

This is intentionally additive. It does not stage or delete the current
checkout's unrelated untracked analysis files.

## Canva boundary

No local Canva source/export was present in the materialized archive used for
this PR. A Canva figure can be added cleanly once its export and design link
are available: place the export under a stable chart bundle, hash it, attach
the design URL in `source/`, and link the chart to its data and renderer. Until
then the figure should be indexed as `EXTERNAL_POINTER_ONLY`, not reconstructed
from a screenshot.

## Acceptance gates

- registry `PRAGMA foreign_key_check` passes;
- R05 has six panels, four linked data files, five chart links, and one
  chart-provenance record;
- PDF/PNG/SVG render hashes match the R05 manifest;
- output is one page and the source/data record counts match the campaign
  boundary;
- old candidate statuses and source pointers remain visible;
- only `results/plots/**` and these release documents are staged.
